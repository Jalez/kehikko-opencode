- **Guards hold while Kehikot restarts.** A heavy command a conversation runs while Kehikot is restarting now waits up to 20 seconds for Kehikot to come back and then goes to the queue, instead of running at once without its guards. If Kehikot stays away, the command runs and the conversation is told it ran unguarded and how to queue heavy work itself.
- **Conversations find this module after a restart.** A conversation reaches the module through Kehikot's stable address for it, then wherever the module is registered now, so a module that came back on another port is still found.
- **A conversation that outlived a restart is told its tools may be gone.** At its next prompt it is told once that Kehikot restarted, how to run heavy work through Queue from the shell if its tools are missing, and that typing `/mcps` and retrying the servers shown as failed brings them back.

## For agents
- If Kehikot's or a module's MCP tools are missing after a restart, run heavy work through Queue's CLI from the shell (`… /kehikot-queue run --kind verify -- <command>` in the background, `… wait <id>` for a run already queued); the note names the path.
